# Conventions

- **Tests** cover pure logic (`test/core/utils/`) and payment widgets (`test/screens/pos/payment_modal_test.dart`), using fakes in `test/fakes/`. There is no integration/e2e harness — verify sync behavior manually against the running app.
- Logging goes through `logDebug()` (`lib/core/utils/app_logger.dart`), which wraps `print` in `kDebugMode` and carries the only `// ignore: avoid_print` in the codebase. Messages use emoji prefixes (🚀 ✅ ❌ 🌐 ⚠️). Never call `print()` directly outside `app_logger.dart`.
- **Búsquedas de texto**: toda comparación de texto escrito por el usuario pasa por `SearchText` (`lib/core/utils/search_text.dart`) — normaliza a minúsculas sin diacríticos y parte la consulta en palabras. No escribir normalizadores privados por pantalla: había dos, con tablas de caracteres distintas, y el buscador principal del POS no usaba ninguno.
- **Accesibilidad**: los objetivos táctiles salen de `AppTapTarget` (`core/theme/app_tokens.dart`), nunca como literales — el mínimo se sube desde el token y debe llegar a todos los controles a la vez. El escalado de fuente del sistema está acotado a `maxTextScale` (1.3×) en `MaterialApp.builder`; `test/core/textscale_test.dart` renderiza a esa escala y falla si algo desborda, así que conviene añadir ahí cualquier pantalla nueva con harness de test.
- **Filas con importe a la derecha** (líneas del carrito, barras de cobro): un solo hijo flexible por fila. Dos `Flexible`/`Expanded` hermanos se reparten el espacio libre según su `flex`, no según lo que cada uno necesita: con flex 1 y 1 el nombre se queda con la mitad exacta aunque el importe ocupe cuatro cifras, el importe se dibuja encogido y lo que le sobra queda como hueco al final de la fila, que descoloca los botones. El importe va sin flex (toma su ancho natural) y el texto largo de al lado en `Expanded`. Cubierto por `test/screens/pos/cart_panel_test.dart` y `test/widgets/multi_currency_amount_test.dart`.
- **Feedback de escaneo**: tono y vibración van juntos dentro de `ScanFeedbackService` (`services/scan_feedback_service.dart`). No sembrar `HapticFeedback` en los puntos de llamada.
- IDs for new offline records are client-generated UUIDs (`uuid` package) so they're stable across the offline→online boundary; the server may return its own `serverId` which is stored alongside.
- Reference docs (Spanish) at repo root: `APP_API_CONTRACT.md`, `API_APP_DOCUMENTATION.md`, `ESPECIFICACIONES_PRODUCTOS_POS.md`, `CONFIGURACION.md`, and `docs/ACTUALIZACIONES_DRIVE.md` describe the API contract, POS product rules, and the self-update flow.
