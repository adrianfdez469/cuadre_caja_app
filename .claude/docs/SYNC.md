# Offline-first sync model (read carefully before touching sync)

- **Reads** (`loadProductos`, `loadPeriodoActual`, `loadMultimonedaConfig`, …): try the API first, **fall back to the SQLite cache** on failure. `*LocalOnly` / `get*Local` variants read disk only (no network) — used to refresh the POS instantly after a sale.
- **Writes** (`crearVenta`): always persist to SQLite **first** (into `ventas_pendientes` with a client-generated `syncId`/UUID and `syncState`), then attempt to sync. A sale never blocks on the network.
- **The queue**: `ventas_pendientes` is the write-behind queue. A `Timer.periodic` (hourly, running a full `fullSync`) plus a connectivity listener drain it via `_syncPendingVentas`. On reconnect, `_onConnectionRestored` runs **ventas-first, then refreshes server inventory last** so local stock isn't clobbered before pending sales are posted.
- **Dos colas en la misma tabla**: `syncState` codifica dos ciclos de vida. Subida: `pending → syncing → synced|error`. **Anulación**: `cancelPending → cancelling →` fila borrada, o `cancelError` si el servidor la rechaza. `getVentasPendientes()` (pending/error) alimenta el POST y `getCancelacionesPendientes()` (cancelPending) el DELETE — **nunca mezclarlas**: una venta en anulación colada en la primera se re-postearía como venta nueva.
- **Anular una venta** (`anularVenta`): sin `serverId` la venta nunca llegó al servidor y se borra en el acto; con `serverId` se marca `cancelPending`, se devuelve el stock de forma optimista y el DELETE lo confirma el servidor. Nunca se borra local por una anulación que el servidor no confirmó. Un rechazo (403 sin permiso, 400 período cerrado) revierte el stock devuelto y deja la venta en `cancelError`, que **no se reintenta sola** — el cajero reintenta o descarta desde la lista de ventas.
- **Orden del drenaje**: ventas pendientes → **anulaciones pendientes** → inventario. Las anulaciones van después del POST porque una venta puede crearse y anularse en el mismo ciclo, y su anulación necesita el `serverId` que acaba de asignarle el POST.
- **Reconciliación de inventario** (`_reconciliarInventario`): `existencia_local = snapshot_servidor − Σ(ventas pendientes) + Σ(anulaciones pendientes)`. El sumando de las anulaciones es imprescindible: esas ventas **sí** están en el snapshot del servidor y **no** están en `getVentasPendientes()`, así que sin él cada refresco de inventario revertiría en silencio el stock que la anulación ya devolvió. La devolución de stock no deshace la desagregación de fracciones (no es invertible); la verdad del padre la pone el servidor.
- **Contadores para la UI** (`VentasProvider`): `errorCount` = `error` + `cancelError` (rechazado por el servidor, se avisa en rojo y lo resuelve el cajero); `porSubirCount` = `pending` + `cancelPending` (sólo espera red, en ámbar); `pendingCount` sigue siendo la suma. Los pinta `BadgedIcon`/`CountBadge` (`lib/widgets/sync_badge.dart`) en el botón "⋯", el menú de acciones y la barra superior. La pantalla de cobro sigue **su** venta sondeando `syncState` por `syncId` (`VentasProvider.getVentaLocal`), no por callback: `onDataRefreshed` hoy sólo lo registra `POSHomeScreen`.
- **`fullSync`** does the full reconcile: período/destinos/monedas → pending ventas → anulaciones → server inventory.
- `SyncService` communicates back to the UI through **callbacks** (`onConnectionChanged`, `onSyncEvent`, `onDataRefreshed`, `onAuthRequired`, `onTokenRefreshed`) that providers register — not streams.
- **Vender sin existencias**: el flag `permitirSinStock` (`lib/core/utils/venta_sin_stock_policy.dart`) relaja toda validación de stock del POS — catálogo, carrito y escáner. Es true sin conexión **y** cuando el usuario activa el ajuste "Vender sin existencias" (`VentaSinStockProvider`, hoja "Cuenta"). Con conexión el servidor puede rechazar la venta con `Existencia insuficiente`: la venta queda en `syncState: error` en la cola y se reintenta desde la lista de ventas.
- Fracción products (sub-units) are "desagregated" into their parent before stock is decremented — see `crearVenta` and `lib/core/utils/producto_pos_rules.dart`.
